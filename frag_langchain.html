LangChain 1.0+ 知识库（从 0.x 到 1.x 完全指南）

LangChain 于 2025 年 10 月发布 1.0（GA），是一次「做减法」的大版本：砍掉数百个历史遗留 Chain/Agent，把框架收敛到单一的高层智能体抽象 create_agent，底层跑在 LangGraph 运行时之上；2025 年 12 月 2 日又推出 1.1，新增模型能力画像（model profiles）。本知识库覆盖包结构、核心 API、中间件、标准内容块、RAG 与迁移，答法遵循「概念 → 用法 → 原理 → 坑点 → 实战」。

一、定位与设计哲学

1.1 发布背景与时间线

  • 2024-06：集成从核心包拆分，部分迁入独立包或 langchain-community。
  • 2024-10：LangGraph 被确立为「不只是单次 LLM 调用」应用的首选编排方式，旧 Chain/Agent 大量被标记弃用。
  • 2025-04：模型走向多模态，langchain-core 的消息格式升级以支持图文/音视频输入。
  • 2025-10：v1.0.0 GA——重构所有 chains/agents，统一为基于 LangGraph 的单一 Agent 抽象；旧版迁移到 langchain-classic。
  • 2025-12-02：v1.1——Chat 模型新增 .profile 能力画像（来自 models.dev 开放目录）。

1.2 设计哲学：一个 Agent 抽象

  • LangChain 团队发现绝大多数使用场景可归结为同一个模式：给 LLM 一些工具 → 调用模型 → 若调用工具则执行并把结果喂回 → 不再调用工具则结束。
  • v1.0 把这个「Agent 抽象」从 LangGraph 的 create_react_agent 提升为 LangChain 主包的 create_agent，并用 LangGraph 作为底层运行时不重新造轮子。
  • 核心收益：只有一种被官方推荐的方式构建 Agent，不再有 AgentExecutor / create_react_agent / 手写 LangGraph 三选一的纠结。
需求推荐说明
快速构建标准智能体LangChain 1.0（create_agent + 中间件）高层抽象，开箱即用
复杂业务流程 / 自定义编排LangGraph 1.0图执行模型 + 持久状态
长周期任务 / 人工审核LangGraph原生人在回路（HITL）
混合工作流两者结合LangChain 构建于 LangGraph 之上，可平滑切换

三、模型初始化 init_chat_model

3.1 统一初始化与多模型切换

  • init_chat_model 用「provider:model」字符串一次性初始化任意厂商模型，切换模型代码零改动。
  • 支持的厂商前缀：openai、anthropic、google、ollama、aws、azure 等，后缀即模型名。
  • 原理：内部按前缀分发到对应厂商包（如 langchain-openai），但调用方只依赖统一的 BaseChatModel 接口。
Python
from langchain.chat_models import init_chat_model

model = init_chat_model("openai:gpt-4o-mini")          # 字符串前缀路由
model = init_chat_model("anthropic:claude-3-5-sonnet")
model = init_chat_model("gpt-4o", model_provider="openai")  # 也可显式指定 provider

resp = model.invoke("用一句话解释 LangChain 1.0")
print(resp.content)

3.2 厂商包与对接国产 / OpenAI 兼容模型

  • 生产环境官方建议直接用厂商包（如 from langchain_openai import ChatOpenAI），主包只做统一接口层。
  • 兼容 OpenAI 协议的第三方（DeepSeek、通义千问、火山方舟、Ollama 等）可复用 langchain-openai，只需改 base_url 与 key。
Python
from langchain_openai import ChatOpenAI

# 以 DeepSeek 为例（OpenAI 兼容协议）
deepseek = ChatOpenAI(
    model="deepseek-chat",
    api_key="sk-...",
    base_url="https://api.deepseek.com",
)

四、工具定义 @tool

4.1 基础用法

  • 用 @tool 装饰普通函数即可把任意 Python 函数变成 Agent 可调用的工具；函数 docstring 即为工具描述（给模型看，务必写清楚）。
  • 类型注解会被自动转为 JSON Schema 入参；TypedDict / pydantic.BaseModel 可做更精细的结构化入参。
Python
from langchain.tools import tool

@tool
def get_weather(city: str, unit: str = "celsius") -> str:
    """查询指定城市的当前天气。

    Args:
        city: 城市名，如 "北京"
        unit: 温度单位，"celsius" 或 "fahrenheit"
    """
    return f"{city} 当前 25 度（{unit}），晴"

print(get_weather.name)        # "get_weather"
print(get_weather.args)        # {'city':..., 'unit':...} 自动生成的 JSON Schema

4.2 结构化入参与状态注入

  • 工具函数可用 InjectedState（from langchain.agents）注入运行时状态（如 context 或图状态），而不占用模型可见的入参。
  • 错误处理：工具内部抛异常会被框架捕获并作为「工具错误信息」回传给模型，让模型自行纠错重试，无需额外包装。
Python
from langchain.agents import InjectedState
from typing import Annotated

@tool
def reply_with_user(ctx: Annotated[dict, InjectedState("context")], msg: str) -> str:
    """把消息和当前登录用户名拼起来返回。"""
    return f"[{ctx['user_id']}] {msg}"

五、消息与标准内容块 content_blocks

5.1 content_blocks：跨供应商统一

  • 现代模型输出已从「纯字符串」演进为内容块列表：推理轨迹（reasoning）、引用（citations）、服务器端工具调用等。
  • v1.0 给消息新增 .content_blocks 属性，提供跨供应商一致的类型化视图；旧的 .content 字段保持完全向后兼容（仍是字符串或厂商原生结构）。
  • 支持的块类型：text、reasoning、image、audio、tool_call、citation 等。
Python
from langchain.chat_models import init_chat_model

model = init_chat_model("openai:gpt-5-mini")
resp = model.invoke("解释一下强化学习")

for block in resp.content_blocks:
    if block["type"] == "reasoning":
        print("思考：", block.get("reasoning"))
    elif block["type"] == "text":
        print("回答：", block.get("text"))

旧写法（v0）需针对每个厂商单独处理 reasoning / thinking 等字段，content_blocks 把这层差异抹平。

5.2 多模态消息

  • 通过 HumanMessage(content_blocks=[...]) 以标准化方式传入文本、图片、音频等，无需再写 OpenAI 风格 / Anthropic 风格两套结构。
  • 图片块可用 url（远程）或 data（base64）提供，并指定 mime_type。
Python
from langchain.messages import HumanMessage

msg = HumanMessage(content_blocks=[
    {"type": "text", "text": "描述这张图片"},
    {"type": "image", "url": "https://example.com/cat.png", "mime_type": "image/png"},
])
res = model.invoke([msg])

5.3 序列化与 LC_OUTPUT_VERSION

  • 默认 content_blocks 不会写回 content 字段。若需把标准块序列化进 content（如发给前端客户端），可开启：
  • 环境变量 LC_OUTPUT_VERSION=v1，或初始化时 init_chat_model(..., output_version="v1")。

六、构建智能体 create_agent

6.1 最小可运行的 Agent

  • create_agent(model, tools, prompt/system_prompt) 是 v1.0 推荐的唯一起点，替代旧 AgentExecutor 与 langgraph.prebuilt.create_react_agent。
  • 返回的 agent 是一个 LangGraph 编译后的图，支持 .invoke() / .stream() / .ainvoke()。
Python
from langchain.agents import create_agent
from langchain.chat_models import init_chat_model
from langchain.tools import tool

@tool
def add(a: int, b: int) -> int:
    """把两个数相加。"""
    return a + b

model = init_chat_model("openai:gpt-4o-mini")
agent = create_agent(model, tools=[add], prompt="你是一个爱用中文的计算助手。")

result = agent.invoke({"messages": [{"role": "user", "content": "3 加 5 等于多少？"}]})
print(result["messages"][-1].content)

Node.js 等价写法：import { createAgent } from "@langchain/langchain"。

6.2 system_prompt 与运行时 context

  • v0 用 prompt 参数；v1 推荐用 system_prompt，并支持 SystemMessage 实例。
  • 静态上下文（如 user_id、session_id，整轮对话不变）通过 context 参数注入，配合 context_schema 声明结构；动态对话状态仍是 messages。旧 config["configurable"] 方式保留兼容。
Python
from dataclasses import dataclass
from langchain.agents import create_agent

@dataclass
class Context:
    user_id: str
    session_id: str

agent = create_agent(model, tools=[add], context_schema=Context)

result = agent.invoke(
    {"messages": [{"role": "user", "content": "你好"}]},
    context=Context(user_id="123", session_id="abc"),
)

6.3 流式调用

  • agent.stream(...) 逐块产出消息增量（含工具调用与最终文本），适合做打字机式 UI。
  • 每个流式事件含 messages 列表，用法与 invoke 一致，只是分多次返回。
Python
for chunk in agent.stream({"messages": [{"role": "user", "content": "讲个冷笑话"}]}):
    for m in chunk.get("messages", []):
        if hasattr(m, "content") and m.content:
            print(m.content, end="", flush=True)

七、智能体中间件 Middleware

7.1 内置中间件

  • 中间件是可插拔的钩子，挂在 Agent 循环的每一步，替代以前「子类化 + 自己包一层」的写法。
  • 内置三件套：
    • Human-in-the-loop：关键步骤暂停，等待人工审批 / 修改。
    • Summarization（摘要）：自动压缩历史对话，防止上下文溢出（1.1 起利用 model profile 更聪明地决策）。
    • PII Redaction（隐私擦除）：内容传递前自动脱敏敏感信息。
  • 1.1 额外提供：OpenAI Moderation 中间件、内置带退避的模型重试。
Python
from langchain.agents import create_agent
from langchain.agents.middleware import HumanInTheLoop, Summarization

agent = create_agent(
    model, tools=[transfer_money],
    middleware=[
        HumanInTheLoop(tools=["transfer_money"]),   # 转账前人工确认
        Summarization(threshold=20),                    # 超过 20 条消息自动摘要
    ],
)

7.2 自定义中间件

  • 实现中间件协议（提供 init / process_model_input / process_model_output 等钩子）即可在循环任意阶段插入逻辑，比如日志、限流、二次校验。
  • 钩子粒度：进入模型前改写输入、模型返回后改写输出、工具调用前/后拦截。

八、结构化输出 Structured Output

8.1 response_format + ToolStrategy

  • v1.0 把结构化输出生成整合进主 Agent 循环，不再额外多调一次 LLM，降低延迟与成本。
  • 用 response_format 指定 pydantic 模型 + 策略（ToolStrategy 走工具调用，或厂商原生 structured output），让模型最终输出强类型对象。
Python
from langchain.agents import create_agent
from langchain.agents.structured_output import ToolStrategy
from pydantic import BaseModel

class WeatherReport(BaseModel):
    temperature: float
    condition: str

agent = create_agent(
    "openai:gpt-4o-mini",
    tools=[get_weather],
    response_format=ToolStrategy(WeatherReport),
    prompt="请查天气并以结构化报告返回。",
)

report = agent.invoke({"messages": [{"role": "user", "content": "北京天气？"}]})
print(report.structured_response)   # WeatherReport(temperature=25.0, condition="晴")

8.2 厂商原生结构化输出

  • 若厂商支持原生 structured output（如 OpenAI / Anthropic），可改用原生策略以获得更好性能；跨厂商统一则用 ToolStrategy 兜底。
  • 细粒度控制权：开发者可决定「用工具调用」还是「厂商原生」，框架在 Agent 循环内统一收敛。

九、持久化与 LangGraph 运行时

9.1 Durable State 与断点恢复

  • LangGraph 是 LangChain 的底层运行时，提供持久化状态：Agent 执行状态自动落盘，服务器重启或长任务中断后可从断点精确恢复，用户无需重来。
  • 内置持久化：通过 checkpointer 保存/恢复任意时刻的工作流，无需手写数据库逻辑，支持多天审批、跨会话后台任务。
  • 用法：给 agent 传入 checkpointer=MemorySaver()（演示）或 PostgresSaver（生产），并在调用时带 thread_id。
Python
from langgraph.checkpoint.memory import MemorySaver

agent = create_agent(model, tools=[add], checkpointer=MemorySaver())
cfg = {"configurable": {"thread_id": "sess-1"}}

agent.invoke({"messages": [{"role": "user", "content": "记住我叫小明"}]}, cfg)
# 下次同一 thread_id 调用会带着上轮记忆继续

9.2 人在回路 HITL

  • LangGraph 对「暂停 → 人工审查 / 修改 / 批准」提供一等公民 API，配合上一节中间件可轻松构建高风险决策的人类兜底。
  • 典型流程：agent 跑到需审批节点 → 暂停并等待人类输入 → resume 带批准结果继续。

十、RAG 与检索（1.0 的变化）

10.1 检索器迁移到 classic

  • v1.0 把绝大多数检索相关能力搬到 langchain-classic：MultiQueryRetriever、ParentDocumentRetriever、Indexing API、CacheBackedEmbeddings 等。
  • 向量库（PGVector、FAISS、Chroma…）与文档加载/切分（DirectoryLoader、RecursiveCharacterTextSplitter）属于 langchain-community 与独立集成包。
  • 主包只保留 init_embeddings 与消息/工具/模型抽象，RAG 编排交给 Agent + 检索工具。

10.2 用 create_agent + 检索工具做 RAG

  • 1.0 的推荐 RAG 模式：把「检索」包成一个工具，交给 create_agent，由模型自己决定何时检索，而不是旧的固定 RetrievalQA 链。
  • 好处：检索与对话、工具调用统一在同一个 Agent 循环里，支持多轮、追问、混合工具。
Python
from langchain.tools import tool

@tool
def search_docs(query: str) -> str:
    """在本地知识库中检索与 query 相关的片段。"""
    hits = vectorstore.similarity_search(query, k=3)
    return "\n---\n".join(h.page_content for h in hits)

rag_agent = create_agent(model, tools=[search_docs],
                          prompt="你是一个严谨的客服，答案必须来自检索结果。")

十二、实战：工具调用 Agent 完整示例

下面把前面知识点串起来：初始化模型 → 定义两个工具 → 加 HITL 与摘要中间件 → 流式运行。

Python
from langchain.agents import create_agent
from langchain.agents.middleware import Summarization
from langchain.chat_models import init_chat_model
from langchain.tools import tool

@tool
def search(query: str) -> str:
    """联网搜索关键词，返回摘要。"""
    return f"关于「{query}」的搜索结果：LangChain 1.0 已发布。"

@tool
def calc(expr: str) -> str:
    """计算数学表达式，如 '23*7'。"""
    return str(eval(expr))   # 仅演示，生产请用安全解析

model = init_chat_model("openai:gpt-4o-mini")
agent = create_agent(
    model,
    tools=[search, calc],
    system_prompt="你是一个严谨助理，先检索再计算，给出带出处的中文回答。",
    middleware=[Summarization(threshold=16)],
)

for chunk in agent.stream({"messages": [{"role": "user",
                              "content": "LangChain 1.0 是哪天发布的？再算一下 23 乘 7。"}]}):
    for m in chunk.get("messages", []):
        if getattr(m, "content", ""):
            print(m.content, end="", flush=True)

十三、1.1 与版本演进（model profiles）

  • v1.1（2025-12-02）：Chat 模型暴露 .profile 属性，描述能力（结构化输出、函数调用等），数据来自开放的 models.dev 目录。
  • 摘要中间件与原生结构化输出策略会读取 profile 做更聪明的决策；create_agent 新增对 SystemMessage 实例的支持、内置带退避的模型重试、OpenAI Moderation 中间件。
  • API 稳定性承诺：1.x 期间不再有重大破坏性变更，直到未来的 2.0。

十四、最佳实践与常见坑

  • 日常开发：pip install langchain + 厂商包即可，从 langchain 主包导入一切；生产尽量用官方厂商包（如 langchain_openai）。
  • 多模型切换：用 init_chat_model("provider:model")，避免散落各处的 ChatXxx 实例化。
  • 国产 / OpenAI 兼容模型：复用 langchain-openai + 改 base_url 与 key（DeepSeek、通义、火山方舟、Ollama 等）。
  • 旧代码不要强行留在主包：Chain / Retriever / Indexing / Hub 已迁移 classic，新项目直接上 create_agent。
  • 结构化输出别再单独多调一次：用 response_format 在主循环内生成，省延迟省成本。
  • 上下文溢出：长对话挂 Summarization 中间件或用 trim_messages 裁剪。
  • 版本：1.0 要求 Python 3.10+；LangGraph 1.0 是底层运行时，复杂编排/持久化/人工审核直接用 LangGraph。
