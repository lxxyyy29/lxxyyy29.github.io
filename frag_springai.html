Spring AI 知识库（Java 生态的 AI 工程框架）

Spring AI 是 Spring 官方出品的 AI 工程应用框架，于 2025-05-20 发布 1.0 GA。它把 Spring 生态的设计原则（可移植、模块化、以 POJO 为积木）带到 AI 领域，核心挑战是把企业数据与 API 连接到大模型。核心 API 是 ChatClient（可移植、易用的模型交互入口）。本库基于 spring.io 官方文档与参考手册整理，答法遵循「概念 → API → 代码 → 实战 → 坑点」。

一、定位与版本

1.1 设计目标

  • 把 Spring 的可移植性、模块化原则应用于 AI 领域，提倡用 POJO 作为应用构建块。
  • 统一抽象：同一套 API 跨多家模型/向量库厂商，切换厂商只需改配置。
  • 不止无状态问答：内置 RAG、对话记忆、工具调用、评估、可观测等「增强 LLM」能力。

1.2 版本与模块

版本状态要点
1.0 GA2025-05-20 稳定ChatClient、Advisors、Tool Calling、VectorStore、MCP、ETL、Eval 齐备
1.1.x稳定新增模型支持与小幅改进（如阿里云 DashScope）
2.0（参考文档）预览/演进中把工具调用循环统一收归 ToolCallingAdvisor，ChatClient 自动注册

四、ChatClient Fluent API

4.1 链式调用

ChatClient 的流式 API 与 WebClient/RestClient 风格一致：构造 prompt → 调模型 → 取结果。

Java
@RestController
class MyController {
    private final ChatClient chatClient;
    MyController(ChatClient.Builder b) { this.chatClient = b.build(); }

    @GetMapping("/ai")
    String generation(String userInput) {
        return chatClient.prompt()
            .system(sp -> sp.param("voice", "pirate"))  // 模板变量
            .user(userInput)
            .call()
            .content();
    }
}

4.2 流式与默认值

Java
// 响应式流式输出
Flux<String> out = chatClient.prompt().user("Tell me a joke").stream().content();

// 在 @Configuration 里固定 system 文本与模型超参
@Bean ChatClient chatClient(ChatClient.Builder b) {
    return b.defaultSystem("You are a friendly bot in the voice of a {voice}").build();
}

十一、Advisors API

11.1 拦截器链模式

Advisor 类似 AOP 环绕通知，在 LLM 调用前后变换数据，提供跨模型/场景的可移植性（记忆、工具、RAG）。

Advisor作用
QuestionAnswerAdvisorRAG：从向量库检索上下文注入 prompt
MessageChatMemoryAdvisor把对话历史加入请求（聊天记忆）
SimpleLoggerAdvisor把内部 trace 打到日志，便于调试
Java
ChatClient client = builder
    .defaultAdvisors(
        new QuestionAnswerAdvisor(vectorStore, SearchRequest.defaults().withTopK(5)),
        MessageChatMemoryAdvisor.builder(chatMemory).build())
    .defaultTools(orderTools, productTools)
    .build();

十三、RAG 实战

13.1 RAG 与工具天然可组合

  • QuestionAnswerAdvisor 在调用前检索并注入上下文；@Tool 在调用中由模型决定是否调用——两者不冲突。
  • 常见场景（如保修咨询）：政策用 RAG（知识库），订单/产品用工具（实时系统）。
Java
ChatClient support = builder
    .defaultAdvisors(
        new QuestionAnswerAdvisor(vectorStore, SearchRequest.defaults().withTopK(5)),
        MessageChatMemoryAdvisor.builder(chatMemory).conversationWindowSize(20).build())
    .defaultTools(orderTools, productTools)
    .build();

13.2 给模型明确指引

当同时有 RAG 上下文与工具时，在 system prompt 里显式说明何时用哪个（如「政策类问题用 CONTEXT，订单/产品细节用 TOOLS」），否则模型可能偏废其一。

十八、最佳实践与常见坑

18.1 实践清单

  • 以 ChatClient 为入口：不要直接调 ChatModel，让 advisor 链、工具注册、流式支持一肩挑。
  • System Prompt 优先于换模型：用清晰的角色/边界/工具规则/system prompt 往往比换模型更有效、更省钱。
  • 结构化输出用 record + @JsonClassDescription：稳定拿到强类型结果。
  • RAG + 工具组合时给模型指引：明确「何时用上下文、何时用工具」。
  • 控制工具数量与记忆窗口：工具过多会稀释模型决策；记忆窗口按需裁剪控制 token。
  • 加可观测性：生产环境务必开启评估与日志，及时发现幻觉/越界。

18.2 版本注意

  • 1.0 GA 是当前主流稳定版；2.0 引入 ToolCallingAdvisor 统一工具循环，迁移时留意 advisor 注册方式变化。
  • 多模态（图文/音视频）取决于底层模型是否支持，使用前核对厂商能力。
