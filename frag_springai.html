Spring AI 知识库（Java 生态的 AI 工程框架）

Spring AI 是 Spring 官方出品的 AI 工程应用框架，于 2025-05-20 发布 1.0 GA。它把 Spring 生态的设计原则（可移植、模块化、以 POJO 为积木）带到 AI 领域，核心挑战是把企业数据与 API 连接到大模型。核心 API 是 ChatClient（可移植、易用的模型交互入口）。本库基于 spring.io 官方文档与参考手册整理，答法遵循「概念 → API → 代码 → 实战 → 坑点」。2026-05-28 发布 2.0 GA：基于 Spring Boot 4 / Framework 7 / Java 21，带来 Jackson 3、setter 全面改为 builder、MCP 进入核心、官方 OpenAI SDK 等重大升级，同时伴随一批破坏性变更（迁移需评估，见第十九、二十章）。

一、定位与版本

1.1 设计目标

  • 把 Spring 的可移植性、模块化原则应用于 AI 领域，提倡用 POJO 作为应用构建块。
  • 统一抽象：同一套 API 跨多家模型/向量库厂商，切换厂商只需改配置。
  • 不止无状态问答：内置 RAG、对话记忆、工具调用、评估、可观测等「增强 LLM」能力。

1.2 版本与模块

版本状态要点
1.0 GA2025-05-20 稳定ChatClient、Advisors、Tool Calling、VectorStore、MCP、ETL、Eval 齐备
1.1.x稳定（1.1.6，2026-05）新增模型支持与小幅改进（如阿里云 DashScope），MCP 开箱即用、Prompt 缓存
2.0 GA2026-05-28 稳定Spring Boot 4 / Framework 7 / Java 21；Jackson 3；MCP 进核心；官方 OpenAI SDK；Redis 记忆/向量；默认 gpt-5-mini

四、ChatClient Fluent API

4.1 链式调用

ChatClient 的流式 API 与 WebClient/RestClient 风格一致：构造 prompt → 调模型 → 取结果。

Java
@RestController
class MyController {
    private final ChatClient chatClient;
    MyController(ChatClient.Builder b) { this.chatClient = b.build(); }

    @GetMapping("/ai")
    String generation(String userInput) {
        return chatClient.prompt()
            .system(sp -> sp.param("voice", "pirate"))  // 模板变量
            .user(userInput)
            .call()
            .content();
    }
}

4.2 流式与默认值

Java
// 响应式流式输出
Flux<String> out = chatClient.prompt().user("Tell me a joke").stream().content();

// 在 @Configuration 里固定 system 文本与模型超参
@Bean ChatClient chatClient(ChatClient.Builder b) {
    return b.defaultSystem("You are a friendly bot in the voice of a {voice}").build();
}

十一、Advisors API

11.1 拦截器链模式

Advisor 类似 AOP 环绕通知，在 LLM 调用前后变换数据，提供跨模型/场景的可移植性（记忆、工具、RAG）。

Advisor作用
QuestionAnswerAdvisorRAG：从向量库检索上下文注入 prompt
MessageChatMemoryAdvisor把对话历史加入请求（聊天记忆）
SimpleLoggerAdvisor把内部 trace 打到日志，便于调试
Java
ChatClient client = builder
    .defaultAdvisors(
        new QuestionAnswerAdvisor(vectorStore, SearchRequest.defaults().withTopK(5)),
        MessageChatMemoryAdvisor.builder(chatMemory).build())
    .defaultTools(orderTools, productTools)
    .build();

十三、RAG 实战

13.1 RAG 与工具天然可组合

  • QuestionAnswerAdvisor 在调用前检索并注入上下文；@Tool 在调用中由模型决定是否调用——两者不冲突。
  • 常见场景（如保修咨询）：政策用 RAG（知识库），订单/产品用工具（实时系统）。
Java
ChatClient support = builder
    .defaultAdvisors(
        new QuestionAnswerAdvisor(vectorStore, SearchRequest.defaults().withTopK(5)),
        MessageChatMemoryAdvisor.builder(chatMemory).conversationWindowSize(20).build())
    .defaultTools(orderTools, productTools)
    .build();

13.2 给模型明确指引

当同时有 RAG 上下文与工具时，在 system prompt 里显式说明何时用哪个（如「政策类问题用 CONTEXT，订单/产品细节用 TOOLS」），否则模型可能偏废其一。

十八、最佳实践与常见坑

18.1 实践清单

  • 以 ChatClient 为入口：不要直接调 ChatModel，让 advisor 链、工具注册、流式支持一肩挑。
  • System Prompt 优先于换模型：用清晰的角色/边界/工具规则/system prompt 往往比换模型更有效、更省钱。
  • 结构化输出用 record + @JsonClassDescription：稳定拿到强类型结果。
  • RAG + 工具组合时给模型指引：明确「何时用上下文、何时用工具」。
  • 控制工具数量与记忆窗口：工具过多会稀释模型决策；记忆窗口按需裁剪控制 token。
  • 加可观测性：生产环境务必开启评估与日志，及时发现幻觉/越界。

18.2 版本注意

  • 2.0 GA 已于 2026-05-28 发布（详见第十九、二十章）：平台升到 Spring Boot 4 / Java 21，setter 全面改为 builder，Chat Memory 强制显式 conversationId，迁移前务必评估破坏性变更。
  • 多模态（图文/音视频）取决于底层模型是否支持，使用前核对厂商能力。

十九、Spring AI 2.0 重大升级（GA：2026-05-28）

2.0 是 Spring AI 的「企业级地基」版本：从 Spring Boot 3.x 全面迁到 Spring Boot 4.0 / Spring Framework 7.0 / Jakarta EE 11，并要求 Java 21。它合并了 67+ 项改动（M1 阶段），并在 M5/M6 持续打磨，最终于 2026-05-28 发布 GA。核心变化是「平台升级 + API 收敛 + 生态增强」，但也带来一批破坏性变更（见二十章）。

19.2 默认模型与官方 OpenAI SDK

  • 默认聊天模型从 gpt-4 改为 gpt-5-mini；依赖默认模型的行为会变化，务必显式指定。
  • 全面接入 官方 OpenAI Java SDK，spring-ai-openai-sdk 模块已合并进 spring-ai-openai；Chat/Embedding/Image/Audio/Moderation 统一走官方 SDK，extraBody 可配。

19.3 记忆与向量存储增强

  • Redis Chat Memory：新增基于 Redis 的会话记忆（含 Starter），支持跨会话持久化、文本搜索、范围查询，并可调 HNSW 参数（M / efConstruction / efRuntime）。
  • Redis Vector Store：支持文本搜索、基于范围的向量查询、HNSW 索引调优。
  • Azure Cosmos DB Chat Memory：新增 Starter。

19.4 MCP 进入核心

MCP 在 1.x 是独立依赖，2.0 合并进核心（基于 MCP Java SDK 0.18.2）。新增服务端注解：

Java
@Component
public class ProductTools {
    @McpTool(name = "get_product", description = "按 ID 取商品详情")
    public Product getProduct(
        @McpToolParam(description = "商品 ID", required = true) String id) {
        return repo.findById(id).orElseThrow();
    }
}

配套还有 @McpResource / @McpPrompt / @McpComplete；一个 Spring Bean 可同时作为 MCP 客户端与服务端（适合 Agent 链式调用）。

19.5 模型生态增强

  • Gemini：ThinkingConfig 支持 ThinkingLevel（思考强度）。
  • Claude：支持 Claude 4.5 Opus/Haiku、Citations API（引用文档片段）、Claude Skills + Files API、四种 Tool Choice 模式（Auto/Any/Tool/None）、原生 web search、thinking 显示/服务层级/数据驻留。
  • ToolSearchToolCallingAdvisor：新增可选 Advisor，按关键词/语义只把最相关的工具定义发给 LLM（tool-index-type=regex|lucene|vector），工具多时能显著降 token。

二十、2.0 迁移：破坏性变更

从 1.1.x 升 2.0 不是小版本：平台、JSON、API 形态都变了。下面是最容易踩的四个坑，建议先升到 Boot 3.5 消弃用，再一次性跳 4.0 并对照本表改代码。

20.1 setter 消失，全部改用 builder

所有模型厂商的 ChatOptions（OpenAi/Anthropic/Bedrock/Mistral/Ollama…）删除了 setter 方法。凡是 setTemperature()/setModel()/setMaxTokens() 都编译不过，必须 builder。

Java
// 1.x：setter（2.0 已删除）
OpenAiChatOptions o = new OpenAiChatOptions();
o.setModel("gpt-4o"); o.setTemperature(0.7);

// 2.0：builder 模式（强制）
OpenAiChatOptions o = OpenAiChatOptions.builder()
    .model("gpt-4o").temperature(0.7).build();

20.2 Chat Memory 必须显式 conversationId

PromptChatMemoryAdvisor 已被移除；记忆类 Advisor 必须显式传入 conversationId，否则跨会话会串记忆。全量审计 chat memory 用法并补 ID。

Java
chatClient.prompt().user(q)
    .advisors(a -> a.param(ChatMemory.CONVERSATION_ID, chatId))  // 2.0 必填
    .call().content();

20.3 工具循环统一收归 ToolCallingAdvisor

ToolCallingChatOptions.internalToolExecutionEnabled 已从所有 ChatOptions 移除（含对应 Boot 配置项）。用户控循环的代码不再编译。迁移方向：

  • 推荐：走 ChatClient + ToolCallingAdvisor（有工具时自动注册，无需 flag）。
  • 用户控循环：直接调 ChatModel，自行检查 chatResponse.hasToolCalls() 并用 ToolCallingManager 驱动。

20.4 Jackson 3 包名与默认行为

Jackson 从 2 升 3，包名由 com.fasterxml.jackson.* 变为 tools.jackson.*（编译期可见，好改）；但日期序列化、字段排序默认值也变了，JSON 形态可能静默变化。务必升前后跑全量集成测试并 diff JSON 输出。

二十一、横向对比：Spring AI 2.0 vs LangChain4j vs Semantic Kernel

Java 生态三大 AI 框架。本站另有「LangChain 1.0+」「Embabel Agent」独立库可作延伸。选型应基于工程决策，而非框架偏好。

21.1 五维对比

维度Spring AI 2.0LangChain4jSemantic Kernel (Java)
定位/绑定Spring 官方，强绑定 Boot 4 / Framework 7独立库，可跑 Spring Boot / Quarkus / Micronaut / 纯 Java SE微软出品，AI SDK 风格
编程模型ChatClient + Advisors 拦截器链AiServices 接口 + 注解，类型安全易 mockPlugin / KernelFunction
版本基线跟随 Spring（Java 21+）JDK 17+，自管 SemVerJDK 17+，Java 版仍早期
RAGAdvisor 抽象，集成 S3 / Bedrock KB 等企业服务切分/向量库/重排/多查询最丰富、切换成本低有，但 Java 版功能少
可观测继承 Actuator / Micrometer，开箱需手动接 Micrometer / OTel较弱
国内模型弱（DeepSeek / 通义可接；智谱已移出主仓库）好（提供商丰富、切换成本低）一般
多 Agent偏空白（2.0 主单 Agent + MCP）编排更成熟Planning Chain
学习曲线Spring 开发者平缓纯 Java 接口，轻量上手快中高
适合Spring 重度团队、企业级、云原生多框架/非 Spring、灵活 RAG、国内模型Azure / .NET 生态

21.2 选型建议

  • Spring 重度团队、要企业级一致性与开箱可观测 → Spring AI 2.0；但需规划 Boot 4 / Java 21 大版本迁移成本。
  • 非 Spring / 多框架 / 重度 RAG / 国内模型（DeepSeek、通义、智谱等） → LangChain4j 更灵活、国内支持好。
  • 已在 Azure / .NET 技术栈 → Semantic Kernel。
  • 可混搭，但务必在架构层做好抽象边界（隔离 ChatClient / AiServices 调用），避免被单一框架绑架。
