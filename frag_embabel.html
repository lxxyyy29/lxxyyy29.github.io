Embabel Agent 知识库（JVM 上的目标导向智能体框架）

Embabel（发音 Em-BAY-bel）是由 Spring Framework 创始人 Rod Johnson 打造的 JVM 智能体框架，构建于 Spring AI 之上，用 Kotlin 编写但对 Java 极其友好。它的核心主张是：用非 LLM 的确定性规划算法（GOAP/A*）动态编排 Actions，把 LLM 调用与普通 JVM 代码、强类型领域模型无缝混合，从而得到「可解释、可调试、可重构」的智能体。本知识库基于官方文档 docs.embabel.com 与 GitHub 仓库整理，答法遵循「概念 → 注解 → 代码 → 原理 → 坑点」。

一、定位与背景

1.1 它解决什么问题

  • 绝大多数 Agent 框架活在 Python 生态；JVM 开发者要么调用 Python 服务，要么在裸 LLM 客户端上手写编排逻辑。
  • LangChain 等依赖 LLM 做路由决策，非确定性、难调试；Embabel 用经典 AI 规划（非 LLM）决定「下一步执行哪个 Action」。
  • 目标：成为在 JVM（尤其是 Spring 应用）上做 GenAI 的「自然方式」，证明模型能力，并逐步演化为「自然语言 PaaS」。

1.2 与 Spring AI / LangChain 的关系

维度Spring AIEmbabelLangChain(1.0)
定位AI 集成基础库（ChatClient/VectorStore/Tool）构建于 Spring AI 之上的智能体编排框架智能体抽象（create_agent）
规划方式无（由你写流程）GOAP/A* 确定性规划 + 每步 ReplanLangGraph 图执行
强类型POJO 映射输出全程强类型领域模型驱动TypedDict / pydantic
语言Java/KotlinKotlin 为主，Java 友好Python / JS

二、核心概念

2.1 五大支柱

  • Actions：智能体执行的离散步骤（一个方法），可调用 LLM、工具或普通代码。
  • Goals：智能体要达成的目标，由系统动态推导，而非硬编码。
  • Conditions：执行 Action 前需满足的前置条件、以及判定 Goal 是否已达成的后置条件；每个 Action 后都会重新评估。
  • Domain Model：支撑流程的强类型领域对象，为 Actions/Goals/Conditions 提供类型信息。
  • Plan：由系统用非 LLM 算法动态编排出的一组 Action 序列；每完成一个 Action 就重新规划（OODA 循环）。

2.2 为什么「不用 LLM 做规划」是关键差异

  • 确定性：规划是经典 AI 算法（A*/GOAP），可解释、可调试、成本极低，不消耗 token。
  • 可扩展：新增 Action/Goal/Condition 即可扩展系统能力，无需改现有的状态机或代码。
  • 强类型：提示词与手写代码通过领域模型干净交互，没有「魔法 Map」，享受完整重构支持。
  • 平台抽象：编程模型与运行时解耦，本地可跑，生产可上更高 QoS 而不改应用代码。

三、快速开始

3.1 项目脚手架

Embabel 暂不兼容 Spring AI 2.0 / Spring Boot 4，请使用 Spring Boot 3.5.x。推荐用 project-creator 或 start.spring.io 建一个空 Spring Boot 项目，再手动加依赖。

xml
<!-- pom.xml：管理 Spring AI BOM 与 Embabel 依赖 -->
<properties>
  <embabel.version>0.4.0-SNAPSHOT</embabel.version>
  <spring-ai.version>1.1.4</spring-ai.version>
</properties>
<dependencyManagement>
  <dependencies>
    <dependency>
      <groupId>org.springframework.ai</groupId>
      <artifactId>spring-ai-bom</artifactId>
      <version>${spring-ai.version}</version>
      <type>pom</type><scope>import</scope>
    </dependency>
  </dependencies>
</dependencyManagement>
<dependencies>
  <!-- shell starter 自带 Spring Shell，便于调试；也可用普通 Web starter -->
  <dependency>
    <groupId>com.embabel</groupId>
    <artifactId>embabel-agent-starter-shell</artifactId>
    <version>${embabel.version}</version>
  </dependency>
  <dependency>
    <groupId>org.springframework.ai</groupId>
    <artifactId>spring-ai-openai-spring-boot-starter</artifactId>
  </dependency>
</dependencies>

四、领域模型（强类型基石）

4.1 用 record / data class 表达类型

领域对象既可由 LLM 生成，也可由用户代码构造/操作。用 Jackson 注解帮助 LLM 理解字段含义，并标记要忽略的字段。

Java
@JsonClassDescription("Person with astrology details")
public record StarPerson(
    String name,
    @JsonPropertyDescription("Star sign") String sign
) {}
Kotlin
data class RelevantNewsStories(val items: List<NewsStory>)
data class NewsStory(val url: String, val summary: String)

4.2 把行为暴露给 LLM

领域对象上的方法若标注 Spring AI 的 @Tool，当其处于作用域时会自动暴露给 LLM 作为可调用工具。注意：工具方法要安全，避免误触发导致删库/改数据。

五、@Agent / @Action / @AchievesGoal

5.1 Kotlin 示例：StarNewsFinder

Kotlin
@Agent(description = "Find news based on a person's star sign")
class StarNewsFinder(
    private val horoscopeService: HoroscopeService,
    @param:Value("\${star-news-finder.story.count:5}")
    private val storyCount: Int = 5,
) {
    // 全部 prompt 类型安全；此 Action 用 LLM 抽取结构化对象
    @Action
    fun extractPerson(userInput: UserInput, ai: Ai): StarPerson =
        ai.withDefaultLlm().createObject(
            "Create a person from this user input, extracting name and star sign: $userInput")

    // 这个 Action 完全不调 LLM，演示 LLM 与普通代码混合
    @Action
    fun retrieveHoroscope(starPerson: StarPerson) =
        Horoscope(horoscopeService.dailyHoroscope(starPerson.sign))

    // toolGroups 声明本 Action 需要 WEB 工具组
    @Action(toolGroups = [ToolGroup.WEB])
    fun findNewsStories(person: StarPerson, horoscope: Horoscope, ai: Ai): RelevantNewsStories =
        ai.withDefaultLlm().createObject("...")

    // @AchievesGoal 标记「完成此 Action 即达成目标」，agent 运行结束
    @AchievesGoal(description = "Write an amusing writeup based on horoscope and news")
    @Action
    fun writeup(person: StarPerson, relevantNewsStories: RelevantNewsStories,
              horoscope: Horoscope, ai: Ai): Writeup =
        ai.withLlm(LlmOptions.withModel(model).withTemperature(0.9))
            .createObject("...")
}

5.2 Java 示例：BlogWriterAgent

@Agent 把类同时标记为 Spring Bean 与 Embabel Agent；每个 @Action 方法的参数即它需要的对象，返回值即它产出的对象，框架据此推断流程路径。

Java
@Agent(description = "Write and review a blog post about a given topic")
public class BlogWriterAgent {

    // 用 OperationContext 访问 AI 能力与运行时
    @AchievesGoal(description = "Produce a reviewed blog post")
    @Action
    public ReviewedPost writePost(Topic topic, OperationContext context) {
        BlogDraft draft = context.ai().withDefaultLlm()
            .createObject("Write a blog post about " + topic, BlogDraft.class);
        // 领域服务做确定性校验/改写
        return reviewService.review(draft);
    }
}

5.3 @Action 的元数据：cost / value / toolGroups

属性含义用途
description动作说明规划与选择时参考
cost相对成本（如 0.1）规划时权衡花费
value相对价值（如 0.8）规划时评估收益
toolGroups所需工具组如 [ToolGroup.WEB]声明前置依赖，不满足则跳过

六、AI 与 LLM 抽象

6.1 Ai 与 OperationContext

  • OperationContext：运行时上下文，通过 context.ai() 拿到 Ai 入口。
  • ai.withDefaultLlm()：用应用配置的默认模型。
  • ai.withLlm(LlmOptions.withModel("gpt-4").withTemperature(0.9))：自定义模型与超参。
  • createObject(prompt, Class)：让 LLM 输出可反序列化为指定类型的对象——把 LLM 当类型安全的解析器。
Java
IncidentSignal signal = context.ai().withDefaultLlm().createObject("""
    Extract an IncidentSignal from the user's message.
    - lon is a number in [-180, 180]; lat in [-90, 90]
    - metric is one of: neuralLatencyMs, cpuUsagePct, powerUsageUw
    User message: %s""".formatted(input.getContent()), IncidentSignal.class);

6.2 模型提供商与自定义 LLM

  • 内置支持：OpenAI、Anthropic、Ollama（设 ollama profile 自动接入本地模型）、Docker（docker profile）。
  • 自定义：对任意提供了 Spring AI ChatModel 的厂商，定义类型为 Llm 的 Spring Bean 即可（参考 OpenAiConfiguration）。配置类应 @ConditionalOnProperty 依赖对应 API Key。

七、规划引擎（GOAP / A*）

7.1 工作原理

  1. Goal Resolver：把用户意图映射到最匹配的目标。
  2. Planning Engine：用非 LLM 的 A* 算法在「当前世界状态」与「目标」之间搜索最优 Action 序列——这是经典 AI 规划，不是让 LLM 决定下一步。
  3. OODA 循环：Observe → Orient → Decide → Act。每执行一个 Action 后重新评估 Conditions 并重新规划，从而对新信息做出反应。
  4. Blackboard：各 Action 的输入/输出对象挂在 Blackboard 上，规划器据此串接（类型 A 产出 → 类型 B 消费）。

7.2 为什么不是状态机

  • 有限状态机 / 线性链是「写死的流程」；Embabel 是「已知步骤的新组合」，能完成从未显式编程的任务。
  • 新增领域对象、Action、Goal、Condition 即可扩展能力，无需改 FSM 定义或既有代码。

八、工具与 ToolGroup

8.1 声明工具组

Action 用 toolGroups 声明运行所需工具；ToolGroup.WEB 等标准组由框架/扩展提供。工具也可通过领域对象上的 @Tool 方法暴露（见 4.2）。

8.2 安全提示

  • 即使最好的 LLM 也可能「手痒」乱触发工具，对会改数据/删数据的方法要特别谨慎。
  • 更稳妥的做法：把危险操作建模为同一领域类上的非工具方法，在代码 Action 里显式调用。

框架内建支持消费 Model Context Protocol 服务器，通过标准接口扩展应用能力；可用 MCP Inspector（npx @modelcontextprotocol/inspector）手动调试。

十、RAG 与向量检索

10.1 embabel-agent-rag 模块

  • 独立模块提供检索增强能力，包含分块增强器（如 ChunkMergingEnhancer）与类型化 Chunk 处理。

十一、多智能体与 A2A

11.1 Agent 联邦

  • 路线图中的关键目标：在 GOAP 模型下演示Agent 联邦（agent federation），多个 Agent 协同完成更大任务。
  • embabel-agent-a2a 模块提供对 Google A2A（Agent-to-Agent）协议的支持，实现跨进程/跨平台的智能体协作。

12.2 单元测试

可轻松单测逻辑与 prompt 是否正确，无需真实 LLM：

Java
public class StarNewsFinderTest {
    @Test
    void writeupPromptMustContainKeyData() {
        StarNewsFinder agent = new StarNewsFinder(mock(HoroscopeService.class), 5);
        var ctx = new FakeOperationContext();
        ctx.expectResponse(new Writeup("Gonna be a good day"));
        // 验证 agent 把正确数据与 prompt 传给了 LLM
        String result = agent.writeup(...);
        assertTrue(result.contains("good day"));
    }
}

十三、成本与预算意识

13.1 预算感知 Agent

  • Action 的 cost/value 元数据让规划器权衡花费，例如：「研究该主题，若仍在摸索阶段花费上限 20 美分」。
  • 设计上鼓励混用多个 LLM（贵的做判断、便宜的做解析），兼顾成本与能力。

十四、最佳实践与常见坑

14.1 实践清单

  • 类型优先：所有 LLM 输出尽量映射为 record/data class，享受重构与强类型。
  • LLM 只做它擅长的：抽取、生成、判断用 LLM；查库、计算、校验用确定性代码。
  • 明确工具边界：会改/删数据的操作不要用 @Tool 暴露给 LLM，改在代码里显式调用。
  • 描述即契约：@Agent/@Action/@JsonClassDescription 的 description 是规划与选择依据，要写清楚。
  • 用 shell 调试：-p -r 看 prompt 与响应，快速定位规划/提示词问题。

14.2 迁移 / 版本注意

  • Embabel 尚不兼容 Spring AI 2.0 / Spring Boot 4，当前用 Spring Boot 3.5.x + Spring AI 1.1.x。
  • 版本演进快（如 1.5.0-SNAPSHOT 主线），引入新特性前先核对对应版本的文档与依赖坐标。
